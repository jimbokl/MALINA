# Как вносить изменения в MALINA

Проект находится на стадии планирования. Перед кодом прочитайте [AGENTS.md](AGENTS.md), [BACKLOG.md](BACKLOG.md) и документы, относящиеся к выбранной задаче. Бэклог — единый источник статусов; предложения без ID сначала оформляются там.

## Рабочий цикл

1. Выберите одну задачу и запишите ожидаемый результат, зависимости и способ проверки. Если данных или прав для публикации нет, отразите это как блокер.
2. Меняйте один пользовательский сценарий или один контракт за раз. Изменение архитектуры сопровождайте ADR в `docs/adr/`.
3. Вместе с кодом обновляйте схему данных, редакторские правила и документацию, которые он затрагивает. Не создавайте публичные факты без источника и проверки.
4. Запустите относящиеся к изменению проверки. Команды сборки и CI появятся после выбора стека в F-04/F-05; до этого не заявляйте, что несуществующие проверки пройдены.
5. В PR укажите ID задачи, пользовательский результат, проверку, ограничения и влияние на данные/публикацию. Для интерфейса приложите подтверждение мобильного и клавиатурного сценариев.
6. После принятия изменения переведите задачу в `verified` только при выполненных критериях из [BACKLOG.md](BACKLOG.md).

Не добавляйте в репозиторий ключи, реальные персональные данные и медиа без подтверждённых прав. Черновики исследования и исходные материалы отделяйте от опубликованных данных.
