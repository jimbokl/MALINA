# МАЛИНА — КЛУБНИКА / malinaklubnika.ru

Стартовая рабочая папка большого продукта для садоводов и рынка ягодных саженцев. Первое ядро — проверенные сведения о малине и садовой землянике, помощь с выбором сорта и путь к надёжному предложению. Долгосрочная идея BerryVerse включает торговлю, инструменты садовода, партнёров и профессиональные сервисы.

**Статус на 24.09.2026:** локальная демонстрационная версия сайта готова; репозиторий [jimbokl/MALINA](https://github.com/jimbokl/MALINA) создан, публикация проверяется. Подтверждённого ассортимента, продавцов и региональных испытаний сортов нет. Домен malinaklubnika.ru зарегистрирован в reg.ru; владелец сообщил о доступе к панели управления. Команда из 100 разработчиков в исходном тексте — сценарий масштаба, а не фактический ресурс.

## Сайт

Нужны Node.js 20+, Python 3 для локального сервера, Rust с целью `wasm32-unknown-unknown` и `wasm-pack` 0.13.1. Внешних npm-зависимостей нет. Сборка использует Rust CLI для выпуска проверенного JSON-каталога и Rust/WASM для регионального движка.

```bash
npm run build
npm test
npm run dev
```

После запуска сайт доступен на `http://127.0.0.1:5181/`. Сборка создаёт `dist/` с самостоятельными HTML-страницами, стилями, графикой, публичным снимком каталога и WASM-модулем. Публичный адрес первого информационного прототипа — `https://jimbokl.github.io/MALINA/`; сборка Pages задаёт `SITE_URL` и `SITE_BASE`. Домен `malinaklubnika.ru` подключается после проверки DNS. [GitHub Pages запрещает использовать Pages для сайтов, главным назначением которых являются коммерческие транзакции или онлайн-бизнес](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits); торговый контур потребует другого хостинга.

Главная, страницы культур, каталог, карточки четырёх сортов, справочный подбор, отзывы, руководство и описание источников доступны без JavaScript; JS нужен для фильтрации, интерактивного подбора и приёма/показа отзывов. Данные и ограничения описаны в [реестре источников](docs/SOURCES.md), архитектура демонстрационной версии — в [ADR 0002](docs/adr/0002-static-site-preview.md).

## Отзывы

Форма на `/otzyvy/` просит только имя или псевдоним, регион, сорт и текст. Под каждым отзывом можно ответить, указав имя, регион и текст; сорт наследуется из обсуждаемого отзыва. Ответы образуют раскрывающиеся ветки. Rust API записывает все сообщения в ту же SQLite, что и каталог; JEV проверяет каждое на спам и пользу для обсуждения. Однословные реплики и бессодержательные ответы не публикуются. Локально форма работает с `REVIEW_API_URL=http://127.0.0.1:8080/api/reviews`; для публичной формы нужен доступный браузеру HTTPS адрес API, поскольку GitHub Pages не исполняет серверный код. Ключ JEV остаётся только в окружении API.

Опубликованные отзывы можно выгрузить из общей базы командой `python3 db/catalog.py export-reviews --out db/public/reviews.json` и коммитить этот файл в GitHub. В нём нет черновиков и причин модерации; GitHub Pages показывает снимок при отсутствии API. См. [ADR 0004](docs/adr/0004-reviews-sql-jev.md).
