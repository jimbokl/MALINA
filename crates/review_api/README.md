# API отзывов

Сервер Axum принимает отзывы в общую SQLite каталога и проверяет текст через JEV.
GitHub Pages показывает опубликованный JSON-снимок и не получает `JEV_API_KEY`.

## Рекомендации сортов (W-13)

Тот же процесс и общая SQLite обслуживают рекомендации читателей:

- `GET /api/votes` → `{"votes":[{"cultivar_slug":"polka","count":0}],"as_of":"2026-09-26T12:00:00Z"}`.
  Возвращаются все сорта из `public_cultivars`, в том числе с нулём голосов;
  порядок — `cultivar_slug`. Это агрегаты мнения читателей, не агрономические оценки.
- `POST /api/votes` ← `{"cultivar_slug":"polka","voter_token":"64 hex-символа","recommended":true}`.
  Ответ: `{"cultivar_slug":"polka","count":1,"recommended":true}`.
  `false` отменяет голос. Повтор одного состояния не меняет счётчик повторно.
- `POST /api/votes/state` ← `{"voter_token":"64 hex-символа"}` → `{"recommended":["polka"]}`.
  Возвращает только голоса по опубликованным сортам, сортировка по slug.

Браузер генерирует случайный 256-битный ключ; регистр hex при хешировании
нормализуется. В SQLite сохраняется SHA-256 ключа, никогда исходный ключ.
Имя, телефон и регион не запрашиваются. JEV в голосовании не участвует.
Неизвестный/снятый с публикации сорт даёт 404, неверный ключ/slug — 400,
ошибка SQLite — 503. Некорректная JSON-схема отклоняется Axum (400/422).
Запись, проверка публикации и подсчёт выполняются в одной транзакции;
уникальная пара сорт/хеш защищает от одновременных повторных запросов.

Перед стартом применить миграции командой `python3 db/catalog.py init --db PATH`.
API проверяет наличие миграции `0009_cultivar_votes`.
Публичный снимок: `python3 db/catalog.py export-votes --db PATH --out db/public/votes.json`.
В экспорт попадают только slug, число и UTC-дата, без хешей, токенов и IP.
Статический сайт использует `VOTE_API_URL` либо адрес рядом с `REVIEW_API_URL`;
GitHub Pages самостоятельно не принимает записи в SQLite.

На один хеш разрешено суммарно 30 запросов POST за 60 секунд (включая state).
Лимитер хранит максимум 4096 хешей в памяти одного процесса; при заполнении
новые ключи получают 429 до освобождения окна. Окно сбрасывается после рестарта.
Это ограничение повторов одного браузера, а не доказательство уникальности
человека: новый ключ позволяет проголосовать снова. Для публичного сервера
нужны общие ограничения запросов на reverse proxy; CORS не защищает от ботов.
Не включать тела этих запросов в журналы reverse proxy или трассировку.

## Контракт

- `GET /api/reviews` — `{"reviews":[...]}` из `public_reviews`; каждая запись
  содержит `id`, `parent_id` (`null` у корня), имя, регион, сорт, текст и даты.
  Возвращаются 50 веток с самой свежей опубликованной активностью, включая
  ответы на старые отзывы, со всеми опубликованными ответами в этих ветках.
  Фильтр `?cultivar=Полка` выбирает корневые ветки указанного сорта.
- `POST /api/reviews` — корневой отзыв:
  `{"display_name":"Анна","region":"Калининградская область","cultivar_name":"Полка","body":"..."}`.
  Ответ внутри ветки:
  `{"parent_id":123,"display_name":"Борис","region":"Псковская область","body":"..."}`.
  Сорт ответа сервер наследует от родителя. Присланный клиентом `cultivar_name`
  у ответа отклоняется. Ответ `{"status":"published"}` (201),
  `{"status":"pending_human_review"}` (202) для сомнительного текста или сбоя JEV,
  либо нейтральное `{"status":"received"}` (202) для отклонённого сообщения.
  Недоступный или неопубликованный родитель
  даёт 409. Глубина ветки ограничена восемью уровнями вместе с корнем.

Текст короче 20 символов не принимается. Проверки обязательных полей,
контактов и адресных маркеров выполняются локально. Для JEV отправляется только **текст отзыва** (`state`), без имени,
региона, сорта, идентификаторов и metadata. Для ответа JEV получает только его
текст и первые 400 символов текста опубликованного родителя, без имён и регионов.
JEV возвращает закрытый выбор
`publishable_useful / spam / low_value / needs_review`. Автопубликация происходит
только при `publishable_useful` с вероятностью не ниже 0.99. Полезный отзыв
содержит конкретное наблюдение о выращивании сорта. Полезным ответом также
может быть предметный вопрос, уточнение или аргументированное несогласие.
Однословное «Бред», оскорбления и общие эмоции отклоняются как `low_value`.
Отправка формы фиксируется в БД как
согласие на обработку и публикацию этих четырёх полей. Ошибка сети,
некорректный ответ или неуверенное решение оставляют отзыв в
`pending_human_review`. Эти записи скрыты из публичного API и JSON-снимка,
но сохраняются для человека. Полезная критика с конкретным опытом допустима.
Обнаруженный контакт или точный адрес отклоняется до сохранения и вызова JEV.
Спам и малоценный текст хранятся в `rejected`; ответ отправителю нейтрален.

0.99 — предварительный порог. Качество решений JEV нужно измерить на размеченных
русскоязычных отзывах. Локальный фильтр проверяет явные контакты; при публикации
свободного текста сохраняется риск пропустить неочевидные контакты.

## Локальный запуск

Создать или обновить общую SQLite БД, применив все миграции каталога:

```sh
python3 db/catalog.py init --db db/local/catalog.sqlite3
```

Миграция 0005 переводит исторические опубликованные отзывы в `pending` до
нового решения JEV; отозванные исторические записи не переносит. Уже
применённая 0003 остаётся неизменной по checksum.
Миграция 0006 добавляет связь родителя, запрещает ответы на неопубликованные
отзывы и скрывает всю ветку, когда корень или промежуточный ответ перестаёт
быть опубликованным. Существующие корневые отзывы остаются без `parent_id`.
Миграция 0007 переводит прежние `pending` в явную очередь
`pending_human_review`; старые записи не удаляются. Одобрение человеком
записывается отдельно от вердикта JEV.

Локальная очередь и решение редактора (не публичный HTTP API):

```sh
python3 db/catalog.py review-queue --db db/local/catalog.sqlite3
python3 db/catalog.py review-decide --db db/local/catalog.sqlite3 \
  --id 42 --decision approved --reviewer editor
```

Для отклонения используйте `--decision rejected`. Ответ можно одобрить только
после публикации его родителя. Оба действия записывают `reviewed_by` и
`reviewed_at`; ранее записанный ответ JEV остаётся в БД для разбора. Перед
ручным решением проверьте текст на контакты и предметность. Очередь и её
содержимое не выгружаются на сайт.

Заранее задать `JEV_API_KEY` в окружении, затем запустить API из корня
репозитория:

```sh
MALINA_DB_PATH="$PWD/db/local/catalog.sqlite3" \
JEV_API_KEY="$JEV_API_KEY" \
ALLOWED_ORIGINS=http://localhost:5181 \
MALINA_BIND_ADDR=127.0.0.1:8080 \
cargo run --manifest-path crates/review_api/Cargo.toml
```

Для локальной сборки сайта: `REVIEW_API_URL=http://localhost:8080/api/reviews npm run dev`.
На loopback разрешён точный HTTP origin; для production нужен HTTPS origin.

## Воспроизводимый контейнер

Команды выполняются из корня репозитория на сервере с Docker. Образ содержит
тот же мигратор SQLite, что используется локально. База лежит в постоянном
томе; повторный `init` применяет только новые миграции. Сначала сохраните
резервную копию рабочей БД перед обновлением образа.

```sh
docker build -f crates/review_api/Dockerfile -t malina-review-api .
docker volume create malina-reviews
docker run --rm --mount type=volume,src=malina-reviews,dst=/data \
  --entrypoint python3 malina-review-api \
  /app/db/catalog.py init --db /data/catalog.sqlite3
```

Создайте вне репозитория файл окружения `jev.env` с `JEV_API_KEY` и правами
доступа только у администратора. Файл не должен попасть в Git или образ.

```sh
docker run -d --name malina-review-api --restart unless-stopped \
  --mount type=volume,src=malina-reviews,dst=/data \
  --env-file /secure/path/jev.env \
  -e ALLOWED_ORIGINS=https://malinaklubnika.ru \
  -p 127.0.0.1:8080:8080 malina-review-api
```

Сервер должен направлять `https://api.malinaklubnika.ru/api/reviews` на
`127.0.0.1:8080/api/reviews` через HTTPS reverse proxy, сохраняя путь и метод;
`/healthz` можно использовать для проверки процесса. На прокси ограничьте
частоту POST и размер тела до 8 КБ, не записывайте тело запроса и настройте
обращение с IP-адресами в логах. Установите регулярную резервную копию тома
с SQLite и проверьте восстановление до открытия формы. Сборке сайта задайте
`REVIEW_API_URL=https://api.malinaklubnika.ru/api/reviews`. Команды
`review-queue` и `review-decide` выполняются в том же томе через
`docker run --rm --mount ... --entrypoint python3` и не доступны по HTTP.

Этот контейнер и runbook подготовлены локально; публичный API ещё нужно
развернуть на сервере и проверить через HTTPS.

В production публикуйте API только через HTTPS reverse proxy. Приложение
не записывает текст или IP-адреса в логи; логи прокси требуют отдельной
настройки. `ALLOWED_ORIGINS` — точные HTTPS origins для браузерного CORS, не
защита от прямых запросов. Нужны ограничения потока запросов на прокси и
резервное копирование рабочей БД. Не помещайте рабочую БД или ключ в репозиторий.
Опубликованные строки можно выгрузить отдельно: `python3 db/catalog.py export-reviews --out db/public/reviews.json`.

```sh
cargo test --manifest-path crates/review_api/Cargo.toml
```

Тесты не вызывают платный JEV API: HTTP-контракт проверяется локальным mock.
Формат запроса основан на [документации JEV Core](https://jevtypesafeai.com/docs).
