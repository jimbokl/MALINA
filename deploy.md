# Публикация сайта «МАЛИНА — КЛУБНИКА»

Актуальный публичный контур — информационный статический сайт из репозитория [`jimbokl/MALINA`](https://github.com/jimbokl/MALINA). Рабочая ветка — `main`, домен — `malinaklubnika.ru`, хостинг — GitHub Pages. Этот файл описывает действующий процесс; состояние конкретного запуска фиксируется в [`handoff.md`](handoff.md) и [`BACKLOG.md`](BACKLOG.md), задача `W-05`.

## Что публикуется

- [`site/scripts/build.mjs`](site/scripts/build.mjs) создаёт `dist/`: самостоятельные HTML-страницы, CSS/JS, графику, публичный JSON каталога и Rust/WASM-модуль подбора.
- [`.github/workflows/pages.yml`](.github/workflows/pages.yml) запускается после push в `main` или вручную, собирает сайт с `SITE_URL=https://malinaklubnika.ru` и `SITE_BASE=/`, загружает `dist/` и публикует его через `actions/deploy-pages`.
- [`.github/workflows/check.yml`](.github/workflows/check.yml) на push и pull request проверяет Rust-крейты, Python-тесты, сборку и `npm test`. Успех публикации и успех проверок сверяются отдельно.
- GitHub Pages не запускает Rust API и SQLite. Публичная форма отзывов начнёт принимать записи только после подключения отдельного доступного по HTTPS API через переменную репозитория `REVIEW_API_URL`. Пока адреса нет, нельзя представлять приём отзывов как работающую публичную функцию.
- Приватную библиотеку книг, локальную SQLite, `.env`, секреты и черновые отзывы в `dist/` и Git не помещать.

## Подготовка изменения

1. Проверьте `git status --short` и последние коммиты. Рабочее дерево может содержать изменения другого агента: добавляйте в коммит только файлы своей задачи, не удаляйте и не перезаписывайте чужую работу.
2. Для локальной сборки нужны Node.js 22 (в CI используется именно он), Python 3, Rust stable с целью `wasm32-unknown-unknown` и `wasm-pack` 0.13.1. Выполните `npm run build` и `npm test`; для изменений каталога, подбора, API или схемы выполните соответствующие команды из `check.yml`.
3. Откройте локальную сборку командой `npm run dev` и проверьте затронутый сценарий на `http://127.0.0.1:5181/`. Сборка не запускает сервер автоматически при обычном `npm run build`.
4. Проверьте, что в исходном HTML есть содержательный текст, правильные `title`, `description`, H1 и canonical. Для агрономических фактов нужны проверенные источники; отсутствие региональных правил должно отображаться как отсутствие подтверждённой рекомендации.

## Публикация

1. Закоммитьте только проверенные файлы и отправьте `main` в `origin` обычным fast-forward push. Не коммитьте `dist/`: его собирает GitHub Actions. Не применяйте force push к опубликованной ветке.
2. Дождитесь успешного завершения обоих запусков: **Site checks** и **Publish informational site to GitHub Pages**. Проверяйте точный SHA опубликованного коммита, а не только зелёный статус более старого запуска. Пример: `gh run list --repo jimbokl/MALINA --limit 5 --json databaseId,workflowName,status,conclusion,headSha,url`.
3. Проверьте фактический сайт на домене: главную, `/malina/`, `/klubnika/`, `/sorta/`, `/podbor/`, `/in-vitro/`, `/otzyvy/`, `/guide/`, `robots.txt`, `sitemap.xml` и ключевые CSS/JS/JSON/WASM-ресурсы. Для изменённого пользовательского сценария проведите браузерную проверку, включая пустое состояние и ошибки консоли.
4. Если сборка или публикация не прошла, изучите лог конкретного запуска, исправьте причину и отправьте новый коммит. Если опубликованный коммит нужно отменить, используйте обычный `git revert` с повторной проверкой, не редактируйте вручную файлы на Pages.

## Домен и HTTPS

25.09.2026 в DNS REG.RU корень домена настроен на четыре A-адреса GitHub Pages: `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`. `www` — CNAME на `jimbokl.github.io`. В настройках Pages назначен `malinaklubnika.ru`. Эти записи уже видны публичным резолверам; повторная смена DNS или снятие/повторное назначение домена требует подтверждённой причины.

По состоянию на 25.09.2026 Pages API возвращает `https_certificate: null` и `https_enforced: false`. Сайт отвечает по HTTP, `www` перенаправляется на корневой домен; HTTPS пока не проходит проверку сертификата. Это **незавершённый деплой** по критерию `W-05`. Активная автоматическая проверка `https-2` ждёт сертификат и должна молчать, пока состояние не меняется.

Когда Pages выпустит валидный сертификат для домена:

1. Сверьте сертификат и обычный HTTPS-ответ для `malinaklubnika.ru` и `www.malinaklubnika.ru` без отключения проверки TLS.
2. Включите `https_enforced` в Pages API и прочитайте настройку обратно.
3. Проверьте перенаправление HTTP → HTTPS, доступность обоих имён, страницы и ресурсы из списка выше, `robots.txt`, `sitemap.xml`, canonical и полный браузерный путь подбора с произвольным регионом России.
4. Запишите результат и ссылки на проверенные запуски в `BACKLOG.md`/`handoff.md`; после полной проверки отключите монитор `https-2`.

До выполнения этих шагов ссылку `https://malinaklubnika.ru/` нельзя считать проверенной. Наличие успешного GitHub Actions само по себе не доказывает доступность HTTPS.
