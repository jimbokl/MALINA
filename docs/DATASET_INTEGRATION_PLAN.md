# Интеграция исследовательских датасетов

Дата проверки: 26 сентября 2026. Задача: **R-01, исследовательская подзадача «реестр и протокол интеграции»**. Связанные функции: FARM-07, FARM-08, MARKET-03, KNOW-03, KNOW-04, R-10, R-11. Сроки и статусы функций ведутся в [BACKLOG.md](../BACKLOG.md).

## Результат этого этапа

Создан [реестр](../research/datasets/registry.csv): 19 уникальных кандидатов из 20 упоминаний в пользовательском обзоре. Два упоминания Raspberry PhenoSet объединены. Для 11 кандидатов установлен первоисточник; для восьми общее название пока не позволяет однозначно определить набор. Проверены страницы, статьи и метаданные; архивы изображений и обучающие данные не скачивались, модели не обучались.

`attachment_claim` хранит сведения обзора, `verified_extent` — только подтверждённые сведения первоисточника. Числа в реестре не являются результатом пересчёта файлов. Проверенная страница лицензии не заменяет проверку состава, версии и прав конкретного архива перед использованием.

Текущий пользовательский путь MALINA — **город → условия выращивания → сравнение сортов → опыт садоводов → предложение продавца**. Для него нужны проверенные сортовые и региональные утверждения. CV-наборы полезны будущим инструментам оценки плодов; они сами по себе не подтверждают название сорта, его пригодность для города, устойчивость или урожайность. Источники подключаем к существующим [предметной модели](DATA_MODEL.md) и [архитектуре](ARCHITECTURE.md).

## 3. Волны интеграции

### Волна 0 — происхождение и контракты, текущий релиз

Результат: этот план и реестр. Следующий шаг внутри R-01 — выбрать **одну** задачу, закрыть её открытые вопросы и зафиксировать протокол. Редакторские источники, опыт садоводов и результаты модели получают разные типы записей. CV-данные не добавляются в текущие региональные правила и карточки сортов автоматически.

Для каждого кандидата перед загрузкой проверяем автора, точную версию, лицензию данных/разметки/кода/весов по отдельности, разрешённую цель использования и атрибуцию. Набор с NC или неясными условиями не включается в коммерческое обучение/инференс без разрешения. В реестре сохраняем текст условий или его идентификатор, дату и основание решения. Контакт с правообладателем — отдельное действие после согласования конкретного запроса.

### Волна 1 — ограниченный офлайн-эксперимент

Первый кандидат — RaspberrySet для подсчёта видимых ягод; альтернатива — клубника 566 после разрешения расхождений версии. Выбираем один результат, фиксируем объём вычислений и хранения, минимальную базовую модель и человеческую разметку до начала. Проверяем классы, повреждённые файлы, дубликаты, исходные кадры и группы съёмки. Сначала воспроизводим простой baseline; более сложная модель нужна при измеренном улучшении.

Данные хранятся отдельно от сайта, Git и `dist`. В репозиторий входят разрешённые метаданные, хеши, манифест эксперимента и отчёт с агрегатами. Изображения не становятся иллюстрациями каталога только потому, что они доступны для обучения. Новые агрономические факты проходят редакционную проверку независимо от эксперимента.

### Волна 2 — местные полевые данные и проверка переноса

Первые 100 фото из РФ нужны для отладки сбора, аннотаций и обнаружения ошибок. Снимки должны иметь законное происхождение, реальную дату, условия, стабильные ID группы/растения/партии и независимую разметку. Несколько снимков одного плода не считаются несколькими независимыми наблюдениями. Объём итоговой проверки определяется покрытием условий, частотой ошибок и требуемой неопределённостью, а не числом 100.

Разделение train/validation/test задаётся **до обучения**, по хозяйству, сезону, партии и исходной серии; все кадры, кропы и аугментации одного объекта остаются в одной части. Отдельный местный holdout закрывается от настройки порогов. Если исходный набор не содержит нужных групп, это отмечается как ограничение: случайный split не подтверждает перенос на новое хозяйство. При отсутствии независимых хозяйств/сезонов выводы ограничиваются реально проверенными условиями.

Изображения из отзывов не присоединяются к обучению автоматически. AI-иллюстрации сортов не участвуют в оценке качества на реальных растениях. Разногласия разметчиков сохраняются и разбираются; неуверенную оценку нельзя превращать в достоверный эталон.

### Волна 3 — публичная функция после результата эксперимента

Публичный помощник показывает область применимости, версию и результат «не могу уверенно оценить», предлагает переснять или обратиться к человеку. Неподдерживаемые культуры, ракурсы и плохое качество изображения дают отказ от оценки. Качество сортировки/подсчёта не обосновывает диагноз, лечение, сортовую идентификацию или точный урожай.

Перед выпуском измеряем задачу на целевых телефонах: время, память, размер модели, загрузку, качество и частоту отказа. **Rust/WASM-инференс выбираем после профилирования**, с загрузкой модели только при запуске инструмента. Если браузер не укладывается в бюджет, возможен изолированный backend с отдельным контрактом и сроком хранения загрузок. GitHub Pages остаётся статическим потребителем; большой ML-пакет не входит в начальную загрузку каталога. Решение о runtime и публичном API оформляется ADR после измерений.

## 4. Контракт данных для следующей реализации

Ниже проект контракта, а не утверждение о созданных таблицах. `null` означает отсутствие сведений; модель не заполняет неизвестное догадкой.

| Запись | Поля и инварианты |
| --- | --- |
| **DatasetVersion** | `dataset_id`, точный `version/record_id`, DOI/URL, `source_id`, aliases, дата проверки, отдельно заявленный/проверенный объём, лицензии с областью действия, разрешённые операции, атрибуция, checksum архива и манифеста после загрузки. |
| **Sample** | ID и hash файла, `dataset_version_id`, `parent_capture_id`, группа серии/партии/растения, псевдоним хозяйства, дата/сезон, страна/регион как место съёмки, условия/камера, оригинальная метка, `annotation_version`, статус разметки и разногласия. |
| **TaxonomyMapping** | Культура связана с `Crop`; исходная метка сохраняется рядом с нормализованной. `Cultivar` связывается только по документированному происхождению растения. BBCH, степень зрелости, дефект и диагноз — разные признаки; правила преобразования версионируются. |
| **GeoScope** | Место съёмки, климат/условия опыта и область подтверждённого переноса — разные поля. Город опыта не порождает `RecommendationRule`. Для пользовательских данных публичная точность географии ограничивается необходимым контекстом. |
| **ExperimentManifest** | Задача и ограничения, versions/hash данных, модель/код, seed, схема split и группы, аудит дубликатов, baseline, метрики, пороги, бюджет, закрытый holdout, ответственный за разбор ошибок. Манифест фиксируется до финального прогона. |
| **Prediction** | `model_version`, поддерживаемая задача, результат, оценка неопределённости, качество входа, `abstained`, причина отказа, область применимости. Результат не создаёт `TraitObservation` или рекомендацию без отдельной проверки. |

Путь интеграции: `Source → DatasetVersion → Sample/Annotation → Experiment → проверенный результат`. Путь подбора: `Source → TraitObservation → RecommendationRule → город/сорт`. Они могут ссылаться друг на друга через доказательства, но остаются разными процессами. `Review` хранит опыт автора; `MediaAsset` — право на публичное изображение; ни одна из этих записей не становится эталонной меткой автоматически.

## 5. Как принимаем результат

До опыта не задаём выдуманные проценты точности. После baseline фиксируем целевые пороги, допустимые ошибки, подгруппы и критерий остановки **до** открытия окончательного holdout. Опубликованные авторами dataset-метрики не являются обещаниями MALINA.

| Проверка | Что измеряем/фиксируем | Условие приёмки |
| --- | --- | --- |
| Происхождение | Доля файлов с источником, версией, правами и hash; соответствие классов. | Все используемые файлы прослеживаются; неподтверждённые исключены. Право на каждую планируемую операцию задокументировано. |
| Независимость | Пересечения hash/близких дубликатов и групп между частями. | Нет пересечений одного исходного объекта/серии; неизвестные группы явно ограничивают выводы. |
| Разметка | Согласие разметчиков, типы разногласий, ошибки эталона. | Спорные примеры выделены; правила согласованы; итог проверен по зафиксированному протоколу. |
| Распознавание | Precision/recall и confusion matrix по классам; для локализации mAP; для счёта MAE/смещение; интервалы неопределённости по независимым группам. | Улучшение относительно baseline подтверждено на закрытой местной выборке, каждый нужный класс имеет достаточные независимые наблюдения. |
| Отказ и уверенность | Калибровка (Brier/ECE при подходящей постановке), ошибка среди принятых ответов, доля отказов, поведение вне области применения. | Пороги выбраны на validation; риск и полезное покрытие соответствуют заранее заданному сценарию, отказ доступен всегда. |
| Перенос | Ошибки по хозяйствам/сезонам/камерам/свету/условиям и известным сортам. | Существенные провалы разобраны; неподтверждённые условия исключены из обещаний интерфейса. |
| Польза | Время выполнения задачи, частота пересъёмки и человеческих исправлений, сравнение с ручной работой. | Пользователь получает проверяемое улучшение при приемлемых ошибках и усилиях. |
| Исполнение | p50/p95 времени, память, байты модели, ошибки загрузки на целевых устройствах. | Соответствие измеренному бюджету; каталог работает без загрузки модели. |

Для FARM-08 отдельно нужны ошибка срока/объёма и покрытие прогнозных интервалов на будущем сезоне; для MARKET-03 — диапазоны входов, чувствительность, источники стоимости и сверка с фактической экономикой. Для KNOW-04 — отрицательные контроли, калибровка сенсора и независимое подтверждение состояния. Это отдельные протоколы, а не побочный результат классификации изображений.

## Следующее действие

Продолжать **R-01**, не создавать второй несвязанный CV-эпик: выбрать R-10 как первый кандидат, зафиксировать вопросы и пределы пилота, проверить допустимую версию RaspberrySet и подготовить протокол локальной съёмки. Подзадача этого релиза завершает исследование источников и планирование; обучение, скачивание архивов и публичный AI-инструмент остаются последующими задачами со своими критериями готовности.
