# Предметная модель и происхождение данных

Статус: предметная модель и действующие инварианты. Реальные таблицы находятся в `db/migrations/`; этот документ также описывает будущие сущности.

## Основные сущности

| Сущность | Смысл | Минимальные поля/связи |
| --- | --- | --- |
| `Crop` | Культура: малина, садовая земляника и будущие культуры. | ID, общепринятое название, таксономические сведения при наличии источника. |
| `Cultivar` | Сорт как биологическая/агрономическая сущность. | ID, культура, каноническое имя, синонимы, статус идентификации. |
| `TraitObservation` | Конкретное утверждение о свойстве сорта. | Сорт, признак, значение и единица, условия измерения, источник, область применимости, дата и редакторский статус. |
| `Region` | Географический контекст рекомендации. | ID, название, границы/тип климата при наличии достоверных данных, версия классификации. |
| `RecommendationRule` | Проверяемое правило подбора. | Входные условия, сорт/группа, причина, исключения, источник, версия и статус публикации. |
| `Source` | Происхождение утверждения. | Автор/организация, название, ссылка или локальный идентификатор, дата публикации/получения, право использования, заметки о применимости. |
| `MediaAsset` | Фото, видео или схема. | Источник, автор, лицензия/разрешение, подпись, изображённый объект, версия файла. |
| `ContentPage` | Руководство или редакционная страница. | Тема, автор, дата проверки, версия, связанные сорта/правила/источники. |
| `Seller` | Реальная сторона продажи. | ID, наименование, контакты и подтверждённые условия; доступ только по роли. |
| `Offer` | Предложение продавца конкретного товара. | Продавец, связанный сорт при достоверной идентификации, товарный формат, цена, наличие, доставка, дата проверки, ссылка/канал заказа. |
| `InventoryLot` | Партия собственного товара, если есть питомник. | Товар, происхождение, количество, качество, место, статусы резервирования/отгрузки. |
| `Order` | Подтверждённое обязательство по продаже. | Покупатель, позиции и продавцы, суммы, доставка, статус, история изменений; вводится только при реальной торговле. |
| `Review` | Отзыв посетителя об опыте выращивания, независимо от справочных фактов о сортах. | Отображаемое имя, регион, название сорта со слов автора, текст, отдельные согласия на обработку и публикацию, статус и результат модерации. |
| `GardenPlanting` | Запись пользователя о своём растении, позже. | Владелец, сорт при известной идентификации, дата/условия посадки, настройки приватности. |

## Инварианты

1. `Cultivar` не содержит цену и остаток. Один сорт может иметь несколько `Offer` с разными продавцами, формами рассады и условиями.
2. Синонимы сорта не создают автоматически новые сорта; спорные совпадения остаются на редакторской проверке.
3. Свойства вроде веса ягоды, урожайности, зимостойкости или устойчивости хранятся как утверждения с условиями и источниками. Противоречия сохраняются, а не перезаписываются последним числом.
4. Рекомендация указывает область применимости. Отсутствие сведений о почве, микроклимате и агротехнике не превращается в уверенный ответ.
5. Ссылка на реестр или внешний API используется только после проверки доступности, условий использования и соответствия сущностей.
6. У опубликованного медиа подтверждено право использования. Чужое фото нельзя считать фотографией собственного питомника.
7. У предложения фиксируется момент последней проверки. Истёкшая актуальность не должна выглядеть как гарантированное наличие.
8. Персональные данные покупателя и сада не попадают в публичные логи/аналитику; доступ и удаление проектируются до появления аккаунтов.
9. Отзывы не становятся источниками агрономических характеристик без отдельной редакторской проверки. Отзыв может называть сорт, которого нет в справочнике.

## Паспорт доказательства для факта и рекомендации

Миграция `db/migrations/0010_evidence_passports.sql` добавляет `evidence_passports`. Паспорт привязан ровно к одному наблюдению `TraitObservation` или правилу `RecommendationRule`; он не подменяет их источник, значение, единицу и статус. Тип доказательства различает публикацию, наблюдение хозяйства, справочный документ и экспертную оценку. Поля фиксируют объект и стадию материала, место и период, измеренные условия, метод, размер выборки, неопределённость, точное место в источнике, применимость и ограничения. Неизвестное остаётся `NULL`, а не выводится из похожих исследований. Права использования учитываются в связанной записи `Source`.

Паспорт сначала создаётся черновиком. В публичный JSON он попадает только после редакторской проверки и только вместе с уже опубликованным наблюдением или правилом. У проверенного паспорта обязательны точный локатор источника, применимость, ограничения и подпись редактора. Внутренний номер образца/партии (`internal_sample_ref`) исключён из публичного представления. Наблюдения без проверенного паспорта пока экспортируются с `evidence: null`, чтобы существующие карточки не пропали при постепенном наполнении. Схема не содержит универсального флага «без вирусов»: такой вывод требует отдельного теста и контекста конкретного образца.

## Партнёрские предложения и собственные партии

Миграция `db/migrations/0008_commerce_publication.sql` вводит две отдельные публичные границы; подробности решения — [ADR 0006](adr/0006-commercial-publication.md). `public_offers` показывает только актуальный партнёрский переход к проверенному продавцу по HTTPS и добавляет пометку о партнёрской ссылке. Цена и наличие не выводятся, если не подтверждены. `public_own_batches` публикует лишь подготовленные к продаже партии с положительным учтённым остатком и условиями местного получения. Внутренний документ происхождения остаётся в рабочей БД. Пустые массивы `offers` и `own_batches` в каталожном JSON нормальны до появления реальных предложений и партий.

## Отзывы и граница публикации

Миграции `db/migrations/0003_reviews.sql`, `0005_reviews_without_token.sql`, `0006_review_replies.sql` и `0007_review_human_queue.sql` создают таблицу `reviews` в общей SQLite базе каталога. Корневая форма передаёт четыре поля: `display_name`, `region` (укрупнённый регион, не адрес), `cultivar_name`, `body`. Ответ передаёт `parent_id`, имя, регион и текст; название сорта наследуется от родителя на сервере. Связь `parent_id` образует вложенную дискуссию. Отправка формы фиксируется в технических полях согласия. Контактные данные, точный адрес и код удаления не запрашиваются.

Статусы: `pending_human_review`, `approved`, `rejected`. Миграция 0007 переводит прежние `pending` в явную внутреннюю очередь, не удаляя записи. Поля `moderation_model`, `moderation_verdict`, `moderation_reason`, `moderation_version`, `moderated_at` сохраняют ответ JEV; допустимые вердикты — `spam`, `not_spam`, `low_value`, `needs_review`. JEV пропускает содержательные наблюдения о выращивании сорта, включая отрицательный опыт, а в ответах — полезный вопрос, уточнение, опыт или аргументированное возражение; пустая оценка вроде «Бред» не публикуется. Автоматический переход в `approved` требует двух согласий, вердикта `not_spam`, заполненной записи модерации и `published_at`. Ручное одобрение ожидающей записи требует двух согласий, `published_at`, `reviewed_by` с префиксом `human:` и `reviewed_at`; исходный вердикт JEV остаётся для аудита. Ответы допускаются только под опубликованным родителем. При сбое или неопределённости JEV запись попадает в `pending_human_review`; локальные команды `review-queue` и `review-decide` дают редактору очередь и решение без публичного HTTP доступа.

`public_reviews` показывает только одобренные записи с видимой цепочкой родителей и отдаёт `id`, `parent_id`, `display_name`, `region`, `cultivar_name`, `body`, `created_at`, `published_at`. Модель и причина модерации остаются внутри БД. `export-public` для каталога не включает отзывы; отдельная команда `python3 db/catalog.py export-reviews --out db/public/reviews.json` создаёт публичный снимок дерева для GitHub Pages. Исходную SQLite с ожидающими и отклонёнными отзывами в GitHub не выгружать.

## Рекомендации читателей

W-13 хранит анонимные голоса в общей SQLite и публикует только агрегаты по опубликованным сортам. Голос связан с сортом и хешем случайного браузерного ключа; он не становится агрономическим фактом, отзывом или оценкой товара. Один активный голос на пару, отмена идемпотентна. Подробный HTTP-контракт, ограничение уникальности браузером и граница экспорта — [ADR 0007](adr/0007-cultivar-votes.md). Рейтинг показывает число активных рекомендаций и равные места, не выдумывает пятибалльную шкалу.

## Поток публикации данных

`получено → нормализовано → связано с источником → проверено редактором → опубликовано → пересмотрено/снято`

Каждый переход оставляет версию и причину. Импорт, агент или ИИ могут создавать черновик; публичный факт появляется после проверки. Ошибка в карточке должна приводить к исправлению конкретного утверждения и затронутых рекомендаций.

## Первый контракт подбора

**Вход:** регион, доступные условия участка и предпочтения пользователя; каждое поле может быть неизвестным. **Выход:** сорт, причины включения, возможные ограничения, использованная версия правил и список источников. Регион выбирается для всей России; если у региона нет опубликованного правила и источника, система показывает справочные записи без ранжирования по региональной пригодности. Низкое качество или недостаток данных дают честный ответ «недостаточно данных» и полезный следующий вопрос, а не искусственный рейтинг «идеальных» сортов.
