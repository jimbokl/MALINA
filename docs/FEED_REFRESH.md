# Обновление товарных фидов и акций

## Источники и расписание

Два товарных фида Admitad и два фида акций привязаны к продавцам `agrosemfond` и `garshinka`. Адреса находятся только в секретах GitHub Actions: `ADMITAD_FEED_URL`, `ADMITAD_FEED_URL_GARSHINKA`, `ADMITAD_COUPONS_URL_AGROSEMFOND`, `ADMITAD_COUPONS_URL_GARSHINKA`. В документах, коммитах и публичном JSON не должно быть адресов с кодом доступа.

`Publish informational site to GitHub Pages` обновляет все четыре источника в 01:23, 07:23, 13:23 и 19:23 UTC, а также после push и по `workflow_dispatch`. Каждая сборка публикует новый статический снимок. Это периодическое обновление, а не показ остатка в реальном времени. Для срочной смены цены или отзыва акции запускайте `workflow_dispatch` и проверяйте опубликованный SHA.

## Правила данных

| Событие в фиде | Каталог и страница товара |
| --- | --- |
| Новый подходящий товар | Добавить карточку и постоянный URL после отбора и генерации текста. |
| Изменилась цена | Заменить цену только из нового проверенного снимка; сохранить дату проверки. |
| `available=false` | Показать «Нет в наличии», убрать кнопку заказа и цену. |
| Товар исчез из фида | Оставить информационную страницу и URL; убрать предложение продавца до нового подтверждения. |
| Фид продавца не загрузился или повреждён | Не переносить его прежние цены и кнопки; предложения другого продавца обновлять независимо. |
| Товар продают оба партнёра | Сохранять отдельные предложения с источником и артикулом, а пользователю показывать одну карточку сорта/товара. |

Цена, наличие и партнёрская ссылка принадлежат предложению продавца. Название сорта, редакционный материал и постоянный URL товара не должны зависеть от текущего остатка. Дубликаты определяются по проверенной идентичности товара, а не только по совпадению текста названия.

Для акций публикуется только редакционно отобранный список ID. Новая акция из фида сначала попадает на проверку условий и релевантности; её нельзя автоматически рекламировать как ягодную. Если отобранная акция пропала, закончилась или у неё сменились условия, следующий снимок убирает либо обновляет её. При значительной смене условий под тем же ID нужно пересмотреть редакционный заголовок.

## Сбой обновления и устаревание

Снимки `db/public/shop-offers.json` и `db/public/shop-coupons.json` живут максимум 12 часов и не коммитятся. Сборка без свежего товарного снимка оставляет каталог, но не публикует цену и кнопку заказа. Сборка без свежего снимка акций не публикует акции. На уже открытой странице браузер скрывает просроченные цены, кнопки и акции по времени снимка; дата окончания отдельной акции проверяется отдельно.

GitHub Pages отдаёт статический HTML. Если запланированная публикация не состоялась, исходный HTML старой страницы остаётся в сети до следующей успешной публикации; браузерный скрипт скрывает устаревшее только при включённом JavaScript. При переезде на серверный каталог проверять цену и наличие при открытии страницы и непосредственно перед собственным заказом.

## Проверка каждого цикла

1. Сверить завершение `Site checks` и `Publish informational site to GitHub Pages` для нужного SHA.
2. Смотреть число товарных строк и доступных предложений **по каждому продавцу**, а также число отобранных акций. Ноль или резкий спад — повод проверить исходный фид и лог.
3. Проверить выборочно: изменение цены, переход в «Нет в наличии», исчезнувший товар, окончившуюся акцию, работающую ссылку на продавца.
4. После изменения логики фидов выполнить `npm run build` и `npm test`; секретные URL не выводить в лог.

Следующий шаг при переносе с Pages: хранить предложения с `source_id`, `product_id`, `checked_at`, `expires_at`; обновлять каждый источник атомарно и хранить журнал изменений цены/остатка. Добавить оповещение о пропущенном цикле, ошибке источника и аномальном падении числа строк.
