# Где продают саженцы сортов малины

## Что считаем

Для каждого датированного среза объявлений о продаже **саженцев малины** считаем число разных объявлений, в которых назван сорт, по городу самого объявления. Заголовок и описание учитываются раздельно. Одна запись, попавшая в несколько поисковых выдач, считается один раз по ID объявления. Если в объявлении перечислены два сорта, запись входит в счёт обоих. При наличии ID продавца считаем также число разных продавцов; в БД остаётся только HMAC-отпечаток ID, а имена, телефоны, адреса и исходные ID продавцов не сохраняются.

Это срез **предложений рынка**, а не статистика посадок или урожая. Поэтому показатель можно использовать для выбора городов и сортов, о которых стоит собрать больше опыта садоводов. Он не меняет региональные правила подбора `D-04` и не доказывает, что растение выращено в городе объявления. Отдельно проверяются происхождение саженцев, условия участка и наблюдения о плодоношении. На сайте не нужно показывать это пояснение возле каждой карточки: достаточно ясного названия показателя «Объявления о продаже саженцев в городе» и ссылки на методику.

## Сбор среза

Сохранять дату, запросы, города, проверенные страницы выдачи и охват в `scope_text`. Сначала запросить все объявления о продаже саженцев малины по каждому выбранному городу, а не искать только знакомые сорта: иначе получится смещённая выборка. Каждую страницу поиска проходить полностью, фиксировать продолжение/пагинацию и число найденных площадкой результатов. Для агрегата использовать город, указанный в самом объявлении, а не город поиска и не географию доставки. Внутреннюю рабочую выгрузку хранить отдельно от публичного сайта.

CSV для импорта: `listing_id,listing_url,city,title,description,seller_id`. Первые четыре колонки обязательны; `description` и `seller_id` могут быть пустыми. В CSV не должно быть колонок с телефонами, именами продавцов, email, контактами и адресами. Для разбора имён используются канонические названия сортов малины и проверенные синонимы из общей SQLite. Сопоставление точное, регистр и `ё/е` не влияют. Неназванные или новые сорта сохраняются как непокрытые объявления; их следует разобрать вручную и при необходимости сначала добавить в каталог сортов. Заголовки вроде «разные сорта малины» не распределяются по сортам автоматически.

```bash
export MARKET_SELLER_HASH_KEY='<локальный секрет>'
python3 db/market_presence.py --db db/local/catalog.sqlite3 import \
  --csv /path/to/avito-raspberry-seedlings.csv \
  --batch-id 2026-09-29-city-survey \
  --observed-on 2026-09-29 \
  --scope 'Города, поисковые запросы, проверенные страницы и пропуски'
python3 db/market_presence.py --db db/local/catalog.sqlite3 report \
  --batch-id 2026-09-29-city-survey --out /path/to/internal-city-variety-counts.json
```

Не записывать секрет в репозиторий или командную строку. При отсутствии `seller_id` импорт работает без секрета, но число продавцов будет неизвестным. Отчёт содержит `listing_count`, `title_count`, `description_count`, `known_seller_count`, `unknown_seller_listings`, общее число объявлений среза по городу и долю сорта среди них для пары город × сорт. Это доля в собранном срезе, поэтому охват запроса важен для сравнения городов. Источник каждого входящего объявления и город доступны в локальной SQLite для проверки. Данные разных срезов не суммировать как «число действующих объявлений»: последняя дата — самостоятельное состояние, а изменение между датами — отдельная динамика.

## Статус 29.09.2026

Схема SQLite и импорт/агрегация реализованы. Проверены на синтетических объявлениях: дедупликация, два города, несколько сортов в описании, число продавцов и отклонение контактных полей. Реального среза Авито в проекте нет; чисел по сортам и городам пока нет. Прямое открытие каталога Авито было отклонено автоматической проверкой Browser Use для `https://www.avito.ru/rossiya/rasteniya` как site-safety. Рабочий следующий вход — полученная владельцем выгрузка объявлений с указанными колонками и охватом поиска.
