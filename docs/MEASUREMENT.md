# Измерение первого выпуска

Статус: схема от 25.09.2026 (`F-06`); фактические счётчики и поисковые кабинеты владельца пока не подключены. Нельзя показывать плановые цифры как наблюдённый трафик.

## Еженедельная таблица

| Вопрос | Источник измерения | Разрез |
| --- | --- | --- |
| По каким тематическим запросам находят страницы? | Яндекс Вебмастер и Google Search Console после подтверждения сайта. | Запрос, страница, показы, переходы, дата. |
| Дочитывают ли материалы и переходят ли к сорту? | События аналитики после установки счётчика; до этого только качественные сессии и доступные логи. | Материал, переход к сорту; без имени или текста отзыва. |
| Завершён ли подбор и что показано? | Событие результата подбора. | Есть проверенное правило / недостаточно региональных данных / ошибка. |
| Полезно ли обсуждение? | Агрегаты состояний отзывов в SQLite, ручная выборочная проверка. | Опубликовано, ожидает человека, отклонено; критические содержательные ответы учитываются как полезные. |
| Ведут ли партнёрские предложения к продавцу? | Событие перехода и данные подтверждённого продавца. | ID предложения и продавца; без цены и наличия, если они не проверены. |
| Были ли продажи? | Отчёт продавца или собственный учёт заказов. | Только подтверждённые заказы, отдельно от кликов. |
| Работают ли внешние каналы? | UTM в аналитике и фактические ссылки на публикации. | Дзен, Pinterest, VK и конкретный материал. |

Сначала подключить один счётчик к собственному домену, затем создать цели по устойчивым именам: `article_to_cultivar`, `selector_complete`, `selector_no_region_data`, `review_submitted`, `affiliate_click`. Для Яндекс Метрики метод `reachGoal` требует заведённую JS-цель; [документация](https://yandex.ru/support/metrica/en/objects/reachgoal). Нельзя считать вызов в коде доказательством получения события: проверить цель в интерфейсе на тестовом переходе. Временный GitHub Pages и отдельный API не должны передавать в аналитику имя, регион, текст отзыва, телефон, IP или ключ JEV.

Фиксировать каждую неделю дату, источники данных, значения и изменение по сравнению с предыдущей неделей. После четырёх полных недель установить цели роста по реальному базовому уровню. При смене домена/хостинга сохранять URL и настройки измерения, сверить канонические адреса, sitemap и цели.
