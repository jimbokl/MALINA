# ADR 0004 — отзывы в общей SQLite и модерация JEV

Дата: 25.09.2026. Статус: реализовано локально.

## Сценарий

Посетитель указывает имя или псевдоним, регион, сорт и текст отзыва. Другой садовод отвечает под ним, указав имя, регион и текст; сорт наследуется, ответы можно вкладывать и раскрывать как дерево. Например, Анна из Калининграда рассказывает о «Польке», Елена из Кишинёва отвечает ей, затем Анна отвечает Елене. Телефон, почта, адрес, учётная запись, код удаления и отдельные флажки не нужны. API записывает сообщения в ту же SQLite, что и каталог. JEV проверяет спам и пользу каждого сообщения: у корневого отзыва нужен конкретный опыт выращивания; в ответе допустимы содержательный вопрос, уточнение или аргументированное возражение. Явный спам и пустые реплики вроде «Бред» отклоняются; сомнительный ответ модели или её сбой отправляет запись в очередь `pending_human_review`, скрытую от читателей до решения человека.

## Хранение и публикация

- Общая рабочая SQLite лежит в `db/local/` и не коммитится вместе с черновиками и секретами.
- Публичное представление `public_reviews` отдаёт только опубликованные отзывы и ответы с видимыми родителями. Поле `parent_id` собирает дерево; корневые отзывы имеют `null`. Команда `python3 db/catalog.py export-reviews --out db/public/reviews.json` создаёт снимок для GitHub Pages. Снимок можно коммитить: он содержит только имя, регион, сорт, текст, даты и связь ответа с родителем.
- При подключённом API страница показывает актуальные опубликованные отзывы. Без API GitHub Pages показывает опубликованный JSON-снимок. После редакционного удаления отзыва снимок нужно пересобрать и опубликовать заново.
- GitHub Pages не запускает Rust API или SQLite. Для публичной отправки нужен доступный браузеру HTTPS API; локально форма работает с loopback API.
- В JEV передаётся текст сообщения и, для ответа, текст родителя после проверки явных контактов и точных адресов. Имя, регион, сорт и сетевые метаданные ему не передаются. Неопределённый ответ не публикуется.
- Очередь ручной проверки остаётся в локальной SQLite, а не в публичном JSON. Проверяющий видит текст и решение модели, может одобрить содержательную критику или отклонить запись. Ручное решение фиксируется отдельно от исходного вердикта JEV; журнал нужен для последующей проверки ложных блокировок. Ошибка модели не удаляет текст безвозвратно.

## Проверка

Локальные автоматические проверки охватывают публикацию, отклонение, очередь, ручное решение и видимость вложенных ответов. Публичный приём требует отдельного HTTPS-развёртывания API и проверки на реальном адресе; наличие статической страницы на GitHub Pages его не заменяет.
