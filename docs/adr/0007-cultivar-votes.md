# ADR 0007: рекомендации читателей и рейтинг сортов

Статус: принято, 26.09.2026. Задача: W-13.

## Решение

У сорта есть один переключаемый голос «Рекомендую». Отзывы остаются отдельными сообщениями об опыте. Рейтинг — число активных рекомендаций, не оценка вкуса по пятибалльной шкале и не региональная агрономическая рекомендация. Сорта с равными числами имеют одинаковое место; сорт без голосов не получает место. Никаких начальных фиктивных голосов.

Голос хранится в общей SQLite. Браузер создаёт случайный 256-битный ключ (64 hex-символа), сервер хранит только SHA-256 ключа. Уникальная пара «сорт, хеш ключа» предотвращает повторное нажатие; POST устанавливает желаемое состояние, не увеличивает счётчик на каждый запрос. Отмена удаляет активный голос. Ключ не помещается в URL, логи, аналитику или публичный экспорт. Имя, телефон, регион и аккаунт не нужны.

Это голос браузера, не доказанная уникальность человека: новый профиль или очистка хранилища позволяют голосовать повторно. Для первого выпуска нужны ограничения частоты запросов и явная методика рейтинга. Более сильная защита вводится по фактическим признакам накрутки, с отдельным решением о профилях.

## Контракт

- `GET /api/votes` → `{ "votes": [{ "cultivar_slug": "polka", "count": 0 }], "as_of": "ISO-8601 UTC" }`. Только опубликованные сорта, включая нулевые значения.
- `POST /api/votes` ← `{ "cultivar_slug": "polka", "voter_token": "64 hex", "recommended": true }` → `{ "cultivar_slug": "polka", "count": 1, "recommended": true }`. `false` отменяет голос. Неизвестные/неопубликованные сорта отклоняются.
- `POST /api/votes/state` ← `{ "voter_token": "64 hex" }` → `{ "recommended": ["polka"] }`. Восстановление состояния без передачи секрета в URL.
- `db/public/votes.json` имеет контракт GET: только агрегаты, без хешей и токенов. Экспорт через `python3 db/catalog.py export-votes --out db/public/votes.json`.
- Статическая сборка читает этот снимок. `VOTE_API_URL` указывает полный URL `/api/votes`; при отсутствии явного значения допустим адрес, полученный заменой конечного `/api/reviews` в проверенном `REVIEW_API_URL`. Публичный браузер читает API, при недоступности показывает датированный снимок. Запись считается успешной только после ответа сервера.

## Последствия

GitHub Pages публикует рейтинг и снимок, сервер Rust принимает голоса. Без подключённого API кнопка не утверждает успешного сохранения. Локально весь сценарий проверяется с настоящим Rust API и временной SQLite. Общие счётчики нельзя заменить `localStorage`.

При изменении продукта до рейтинга по звёздам потребуется новая шкала, правила выборки и отдельная миграция. `AggregateRating` для этих рекомендаций автоматически не добавляется.
