# Несколько продавцов в товарном каталоге Admitad

## Контекст

Магазин уже публикует карточки из фида Агросемфонда. В фиде Гаршинки есть дополнительные товары малины и клубники, а часть растений встречается у обоих продавцов. Пользователю нужна одна страница растения с актуальными предложениями; старые адреса и карточки должны сохраниться. Фиды обновляются независимо, а цена и наличие пригодны для публикации только после проверки конкретного предложения.

## Варианты

1. Отдельная витрина каждого продавца: проще загрузка, но возникают повторные страницы одного растения.
2. Общий каталог с отдельными записями SKU и предложения, а публичную страницу объединять по проверенному названию и культуре.

## Решение

Выбран второй вариант для задач `C-01` и `C-02`. Конфигурация источника задаёт категорию, продавца и разрешённые домены товарной ссылки и фотографии. ID Гаршинки получают префикс `g-`, новые URL — стабильный префикс `tovar-g-`. Реестр хранит все отобранные SKU, а повторные фасовки и совпавшие растения ведут к одной канонической странице. На ней каждое доступное предложение выводится отдельно с названием продавца, ценой и партнёрской ссылкой. Исходные URL Агросемфонда не меняются.

Каждый CSV загружается независимо через HTTPS и проверяется по своему источнику. Если один фид недоступен, сборка использует только подтверждённые предложения другого; если недоступны оба, цена и кнопки заказа снимаются. Недоступные или некорректные строки остаются в каталоге без обещания покупки. Секретные URL фидов и рабочий снимок предложений не коммитятся.

## Последствия и пересмотр

Витрина получает страницы новых растений и выбор продавца для совпавших позиций. Статическое объединение названий требует редакционной проверки спорных совпадений; SKU и источник сохраняются раздельно, чтобы ошибку можно было исправить без потери исходной записи. Пересмотреть подход, если число ошибочных объединений или ручных исключений станет значимым; тогда потребуется явный реестр связей товаров с растениями.

## Расширение 12.10.2026: onlinesemena.ru (C-11)

Тот же контракт применяется к третьему продавцу: собственные домены, валюта RUB, префикс SKU `o-` и новые постоянные URL `tovar-o-`. Совпадения имени и культуры и известные обозначения фасовок объединяют предложения на уже существующей странице. Иные обозначения сорта сохраняются, чтобы не подменять идентичность. Секрет `ADMITAD_FEED_URL_ONLINESEMENA` передаётся через Actions; исходный CSV и адрес остаются вне Git.

## Расширение 12.10.2026: атрибуция перехода и placement (C-02/F-06)

Все активные фидовые предложения трёх продавцов получают SubID до перехода на сайт продавца: `subid=p1_<32 hex>` — детерминированный placement ID; `subid1=<seller>_<offer>` — короткая читаемая пара продавца и предложения (длинные offer ID ограничиваются с коротким hash suffix); `subid2=shop_offer` — тип placement. Не используем `subid3`; не заменяем и не удаляем исходные tracking path, `ulp`, `erid` и остальные query-параметры. Максимум полей `subid`/`subid1`/`subid2` — 50 символов.

При обычном или среднем действии на актуальную ссылку, если посетитель не отключил аналитику и браузер поддерживает криптографический генератор, скрипт создаёт новый непостоянный `affiliate_click_id=c1_<32 hex>`, заменяет `subid` перед переходом и отправляет этот же ID вместе с детерминированным `attribution_id` в существующую цель `affiliate_click`. Никакой ID клика не записывается в хранилище браузера. Без JavaScript, при отказе от аналитики или когда клик нельзя перехватить остаётся только placement fallback `p1_…`; его нельзя трактовать как точную связь клика и заказа.

Публичный `/data/affiliate-attribution.json` фиксирует детерминированную связь ID с canonical path, seller, offer, product, placement и известным cultivar, но не содержит affiliate URL. При объединении отчётов Admitad точный click join возможен только по совпавшему `c1_…`; `p1_…` годится для агрегированной оценки placement. Отчёт продавца без возвращённого SubID остаётся неатрибутированным. Реализация и тесты не подтверждают, что значения уже принимаются отчётами каждого продавца; проверка на реальных заказах и комиссиях остаётся отдельной приёмкой.
