# Ягодный тезаурус: рабочий контракт

Тезаурус связывает слова садовода с точными понятиями каталога и агрономических наблюдений. Книги дают кандидатов и контекст, но не публикуются целиком и не становятся автоматическим источником без проверки.

## Единица данных

| Поле | Смысл |
| --- | --- |
| `term_id` | Постоянный идентификатор понятия, не зависящий от написания. |
| `preferred_label_ru` | Основной русский термин. |
| `aliases_ru` | Варианты написания и бытовые названия; каждому нужен источник. |
| `definition_ru` | Собственная краткая формулировка после экспертной проверки. |
| `scope` | Культура, часть растения, агроприём, болезнь, свойство сорта, регион и т. п. |
| `relations` | `broader`, `narrower`, `related`, `synonym_of`, `not_same_as`. |
| `evidence` | ID книги, страница файла или раздел, цитируемый термин, дата проверки. |
| `review_status` | `candidate` → `reviewed` → `published`; спорное остаётся кандидатом. |

## Первый редакторский проход

1. Извлечь заголовки, указатели и варианты слов из приватных Markdown-копий в приватную очередь кандидатов.
2. Разделить сорт, культуру, тип плодоношения, агроприём, болезнь и коммерческий товар. Не объединять «клубнику» с любой земляникой без контекста.
3. Проверить определение и связи по оригинальной странице и независимому современному источнику. Зафиксировать применимость по времени и региону.
4. Публиковать только собственные короткие определения с библиографией. Полные тексты, изображения, длинные цитаты и OCR-ошибки оставлять в `knowledge/private/`.

Начальные узлы для проверки находятся в [term-seed.json](term-seed.json). Это названия кандидатов, не готовые определения или рекомендации. `scripts/index_thesaurus.py` создаёт локальный индекс мест, где встречаются термины; он не копирует в публичный каталог фрагменты книг.
