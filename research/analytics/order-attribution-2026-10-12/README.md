## Поисковая атрибуция

Свежие визиты, посадочные страницы и цели Метрики **не получены**: `/stat/traffic`, `/list` на `metrika.yandex.ru`, а также международный адрес показали сообщение технической недоступности. Владелец подтвердил общий временный сбой Яндекса. Это неизвестные значения, а не нулевой трафик.

Исторические ссылки не передавали SubID. Поэтому задним числом связать 185/267 кликов с конкретной поисковой посадочной и товаром нельзя. Старый срез Метрики 27.09–06.10 (72 визита, 3 поисковых; два `affiliate_click` из внутренних переходов) не смешивается с новым окном Admitad. GSC и Вебмастер дают агрегаты запросов; отдельный запрос не приписывается конкретному заказу без наблюдаемой связи.

**Какая страница реально заработала деньги: пока такой страницы в отчёте нет.** У всех продавцов 0 зарегистрированных продаж; сравнительный рейтинг по доходности отсутствует. Не увеличивать вес Гаршинки только из-за количества кликов. Следующее решение о продавцах и коммерческих страницах принимать по подтверждённой комиссии органической когорты, покрытию атрибуции и отменам после сверки, а не по общим переходам.

## Внедрённая связка для следующих действий

1. Статический `subid=p1_…` определяет страницу товара, продавца, артикул и место кнопки. Публичный manifest `/data/affiliate-attribution.json` не содержит адресов партнёрских переходов.
2. При включённой аналитике обычный/средний клик получает новый случайный `subid=c1_…`; тот же `affiliate_click_id` и стабильный `attribution_id` отправляются в цель `affiliate_click`. ID не сохраняется в браузере и не содержит данных человека или запроса.
3. `c1_…` из действия Admitad связывается с хитом цели, затем по `visitID` — с источником и посадочной страницей визита Метрики. Отказ от аналитики, отсутствие JS и контекстное меню оставляют `p1_…`: здесь возможен только итог по кнопке, без органического источника.
4. Заказ учитывается отдельно от перехода. Суммы разделены на pending, approved, declined, credited (`processed`) и paid; валюты не складываются. Товар клика не доказывает состав купленной корзины.

Контракт: [MEASUREMENT.md](../../../docs/MEASUREMENT.md), [ADR 0009](../../../docs/adr/0009-multiple-admitad-sellers.md). **Работа кода не заменяет получение параметров в кабинетах. C-02/F-06 остаются in_progress.**

## Воспроизводимая сверка

`scripts/reconcile_affiliate.py` читает приватные экспорты, соединяет только наблюдаемые ID и выпускает агрегаты без orderID, visitID и clickID. Тестовые заказы существуют только в явно синтетических unit-тестах.

Входы сохранять в `db/local/`:

- Admitad actions: полный JSON с `results` из [Publisher reports](https://developers.mitgo.com/hc/en-us/articles/34481279018130-Publisher-reports), отфильтрованный по `website=3005376`, всем трём программам и статусам. Обойти все страницы API/экспорта. Добавить в envelope `website_id: 3005376`, `complete: true`, `period`; исходные поля `action_id`, `advcampaign_id`, `action_type`, `order_id`, `status`, `currency`, `payment`, `subid`, `processed`, `paid` сохранить. `complete` ставить после сверки количества строк. Для текущего пустого отчёта сохранено отдельное нормализованное наблюдение UI, оно не выдаётся за ответ API.
- [Metrika hits TSV](https://yandex.ru/dev/metrika/ru/logs/fields/hits): `ym:pv:visitID,ym:pv:goalsID,ym:pv:params`. Парсер выбирает только цель `664725910` и объекты её параметров с `c1_…`.
- [Metrika visits TSV](https://yandex.ru/dev/metrika/ru/logs/fields/visits): `ym:s:visitID,ym:s:startURL,ym:s:lastTrafficSource,ym:s:lastSearchEngineRoot`. Модель источника — последний переход данного визита. URL нормализуется до пути без query/hash. Для источника клика нужны визиты за окно кликов, включая lookback до периода заказов; одно окно регистрации заказов не задаёт знаменатель CR.
- Manifest: сохранять снимок каждой публикации в приватной истории и объединять строки разных выпусков. Старые предложения могут исчезнуть до подтверждения заказа. Неизвестная метка остаётся `unattributed`.

```sh
python3 scripts/reconcile_affiliate.py \
  --actions db/local/actions-complete.json \
  --manifest db/local/affiliate-manifest-history.json \
  --hits db/local/hits.tsv --visits db/local/visits.tsv \
  --out db/local/attribution-aggregate.json
python3 -m unittest db.tests.test_affiliate_reconciliation -v
```

Без экспортов Метрики параметры `--hits/--visits` опускаются: источник и число её событий остаются неизвестными. Скрипт проверяет неполную пагинацию, чужую площадку, конфликты ID и продавцов; не суммирует вложенные positions повторно. Заказы уникальны по продавцу и `order_id`, но могут встречаться в разных статусных/атрибуционных группах при разделении заказа. Проверять поля `unknown_paid_actions`/`unknown_processed_actions`: сумма явно выплаченных строк не означает полную выплату, если флаг отсутствует.
